# 알림 (Notification)

## 채널

- **푸시**: Web Push API + VAPID 키 (직접 구현, 의존성 0)
- **이메일 폴백**: Resend (푸시 발송 실패 시)

## 발송 조건 (AND)

알림은 다음 두 조건을 **모두** 통과해야 발송:

### 1. 매장 알림 채널 설정
- 사장이 매장 단위로 선택: 푸시 / 이메일 / 푸시+이메일
- **사장만 설정 가능** (직원·매니저는 변경 불가)
- 매장 직원도 매장 설정에 따라 수신

### 2. 고객 알림 설정
- 고객 본인이 마이페이지에서 글로벌 ON/OFF
- 채널별 분리: 푸시 ON/OFF, 이메일 ON/OFF
- 둘 다 OFF 시 어떤 알림도 못 받음 (본인 책임)

> 매장이 푸시만 보내는데 고객이 푸시 OFF면 → 미수신 (이메일도 안 감, 매장 설정 우선)
> 매장이 푸시+이메일 보내는데 고객이 푸시 OFF / 이메일 ON이면 → 이메일만 수신

## 폴백 트리거

- 푸시 서버 응답 실패 (5xx 또는 push subscription 만료) → 자동으로 이메일 폴백 (매장이 이메일도 활성화한 경우)
- 사용자가 푸시 받았지만 안 본 경우는 폴백 X (시스템은 알 수 없음)

## 알림 종류

### 고객
- 예약 신청 완료 (예약금 매장: "입금 대기")
- 예약 확정 (예약금 매장: 입금 확인 완료 시)
- 예약 거절 (사유 표시, 예약금 환불 안내)
- 예약 변경 안내 (직원·사장이 변경한 경우)
- 예약 1시간 전 리마인더
- 예약 취소 안내
- 트레이너 측 변경 요청 (전화 받으세요)

### 사장·매니저·담당 직원
- 새 예약 신청 (예약금 없는 매장: 자동 확정 알림)
- 새 예약 신청 + 입금 확인 요청 (예약금 있는 매장)
- 1시간 전 다음 예약 리마인더
- 매장 구독 만료 임박

## 인프라

### Web Push 직접 구현
- VAPID 키 페어 생성 (서버 시드)
- Service Worker 등록 (Next.js 16 PWA)
- 클라이언트가 push subscription 생성 → 서버에 저장
- 서버에서 `web-push` 라이브러리로 발송
- iOS Safari PWA: 16.4+ 지원, "홈 화면 추가" 후 활성화

### 이메일 (Resend)
- 가입 magic link·비번 재설정·트레이너 초대·알림 폴백 모두 동일 서비스
- 무료 한도: 3,000 메일/월, 100/일 (출시 초기 충분)
- 도메인 인증 필요 (배포 시 설정)
- OTP 6자리 코드는 사용 안 함 ([auth.md](./auth.md) 참조)

## 알림 로그

- `notification_log` 테이블에 발송 기록
- 필드: 수신자·종류·채널·결과(성공/실패)·시각·폴백 여부
- 관리자 화면에서 조회 (V2)

## 채널 정책 (확정)

- 푸시(Web Push) + 이메일(transactional) 두 채널만 사용. **SMS·문자는 비용 사유로 사용 안 함**.
- 사장 → 회원 단체 발송(broadcast/marketing) 기능도 도입하지 않음. 알림은 시스템 트리거 transactional만.

## V2 추가 예정

- 알림 종류별 채널 차등 (예: 리마인더는 푸시만, 확정은 푸시+이메일)
- 사장이 매장별 알림 종류별로 ON/OFF 설정
- 직원 본인이 알림 OFF 가능 (매장 설정 무시)
